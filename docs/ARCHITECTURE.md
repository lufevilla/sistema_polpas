# Arquitetura do Projeto Sistema Polpas

## Visão Geral

App Flutter + Rust (via flutter_rust_bridge) para gestão de polpas artesanais. Backend em SQLite via Rust, frontend em Flutter com arquitetura MVC/C.

## Stack

- **Frontend:** Flutter 3.41.9, Dart
- **Backend:** Rust, rusqlite, flutter_rust_bridge 2.13.0
- **Banco:** SQLite (`banco_de_dados.db`)
- **Plataformas:** Android, Linux, Web

## Padrão de Camadas (pages)

Cada domínio segue o padrão:

```
page/ 
├── models/          # Modelos de dados locais (se necessário)
├── *_page.dart      # UI (StatefulWidget)
├── *_controller.dart # ChangeNotifier (estado + lógica)
└── widgets/         # Componentes reutilizáveis da página
```

### Regras
- **Page** → Apenas UI, delega lógica ao controller
- **Controller** → ChangeNotifier, gerencia estado, chama services
- **Widgets** → Stateless, recebem dados via construtor
- **Models** → Podem ter factories para conversão (ex: `fromProduto()`)

## Fluxo de Dados (Backend → Frontend)

```
SQLite (banco_de_dados.db)
    ↓
Rust Service (rust/src/api/*_service.rs)
    ↓  #[flutter_rust_bridge::frb] ou pub async fn
FRB Codegen (rust/src/frb_generated.rs)
    ↓  auto-generated
Dart Bindings (lib/src/rust/api/*_service.dart)
    ↓  auto-generated
Dart Wrapper (lib/rust/*.dart)  ←手書き
    ↓  import por controllers
Controller (lib/pages/*/*_controller.dart)
    ↓  ChangeNotifier + notifyListeners()
Page (lib/pages/*/*_page.dart)
    ↓  AnimatedBuilder / Consumer
Widgets
```

##/flutter_rust_bridge.yaml

```yaml
rust_input: crate::api
rust_root: rust/
dart_output: lib/src/rust
```

## Comandos Úteis

- `flutter_rust_bridge_codegen generate` — Regenerar bindings Dart↔Rust
- `cargo check` (em rust/) — Verificar compilação Rust
- `flutter analyze` — Verificar compilação Dart

## Tabelas SQLite

- `clientes` — id, nome, cadastro, telefone, cep, logradouro, numero, complemento, bairro, municipio, uf
- `estoque` — id_merc, nome_merc, quantidade_est, quantidade_minima, valor_unitario
- `pedidos` — id_pedidos, cliente_id (FK), data, valor_total
- `itens_pedido` — id_item, pedido_id (FK), produto_id (FK→estoque), quantidade, valor, subtotal
